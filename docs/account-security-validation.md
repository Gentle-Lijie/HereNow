# 后台密码与 Passkey 验收

日期：2026-10-15。对应 Spec v1.6 第 4.1、11、12、13.1、15 节。

## 实现

- 顶部新增“账号安全”入口 `/admin/security`。管理员和操作员只管理自己的密码与凭证，不改变活动权限。
- 改密验证当前密码；密码非空即可，没有长度、字符组合或与旧密码不同的要求。在用户行锁与事务中更新 Argon2 摘要、撤销全部后台会话、清除该用户未完成的注册挑战并审计；已有 Passkey 保留。密码登录在验密后重新锁定用户并核对摘要，避免竞争改密后旧密码签发会话。
- 添加／移除 Passkey 均须当前密码与有效后台会话；最多 10 个，名称 1–80 字。列表仅返回管理 ID、名称及时间，不返回 credential ID、公钥或用户句柄。删除只作用于当前账号，同时撤销其他后台会话。
- SimpleWebAuthn server 14.0.3 / browser 14.0.0 固定版本；无自制验签。注册要求可发现凭证和用户验证；无账号输入的 Passkey 登录验证 Origin、RP ID、挑战、签名、用户句柄、UV 和计数器，支持同步 Passkey 的零计数器。
- 迁移 `007_account_security.sql` 增加用户随机、不透明且唯一的 WebAuthn 句柄，创建 `passkeys` 和 `webauthn_challenges` InnoDB 表。句柄首次注册时在用户锁下生成并保留，不依赖密码或密钥轮换。credential ID 二进制全局唯一；用户删除时级联删除凭证与注册挑战。
- 挑战绑定浏览器、用途和固定 5 分钟时效，注册还绑定原账号与后台会话。验证前独立事务单次消费；验签失败也不能重放，数据库后续故障需要重新开始认证。过期挑战加入常规 cleanup。
- Passkey 登录更新计数器、签发会话、写审计在同一用户锁事务完成；删除竞争由该锁串行化。全部写接口沿用 Origin／CSRF，敏感路由独立每 IP 每分钟限 10 次，不返回账号／凭证枚举列表。
- 浏览器模块按需加载，仅后台登录／安全路由使用；页面卸载取消请求／WebAuthn 操作并清空密码草稿。错误区域可获取焦点，表单验证定位首个错误，所有按钮及账号安全输入至少 44 px 高。

## 配置与限制

- 生产先备份，再 `npm ci`、`npm run db:migrate`、构建并重启 API，然后更新前端。API 启动检查迁移 007，避免用旧数据库结构提供不完整认证能力。
- `APP_ORIGIN` 必须是浏览器实际访问的完整源（协议、主机、可选端口，不含路径／尾斜线），例如 `https://checkin.lijie.space`。RP ID 自动使用其主机名，不能填源站 API 域名。Passkey 属于注册时的站点；更换主机名需重新注册。
- 需要 HTTPS，localhost 用于本地开发。浏览器、设备或内置 WebView 不支持时使用密码登录。已注册凭证的设备验证由系统执行，服务器不获取指纹／面容数据或私钥。
- 2026-10-15 已在服务器 Node 22.14.0 / MySQL 8.4.5 的独立 `herenow_test` 完成验证：新增 19 项认证测试使用业务账号通过，全量 118 项使用隔离库测试管理账号通过（包含需触发器权限的故障注入测试），没有扩大生产业务账号权限。隔离库及临时权限已清理。生产已完成迁移与发布。
- 尚未使用真实 Touch ID、Face ID、Android 验证器、实体安全密钥、密码管理器同步或跨设备扫码验证。虚拟验证器不能替代这些真机兼容性结论；未执行新认证接口的生产压测。
- 部署方密码重置命令只重置密码并撤销会话，不移除已有 Passkey。密码恢复后可在账号安全页验密移除遗失或不可信凭证；密码修改本身不撤销 Passkey。
