# 管理员当前位置定位验收

日期：2026-10-14。对应 Spec 第 8.4、8.5、8.6、15 节；延续身份字段和地图接入修复。

## 行为

- 管理员尚未设置活动中心时，打开位置弹窗自动尝试浏览器定位；浏览器按自身权限设置请求授权。已有活动中心保持原位，提供“定位到我附近”按钮用于主动定位或重试。
- 标准 Geolocation 请求使用 `enableHighAccuracy=true`、`maximumAge=0`、`timeout=10000`，另有等待期限兜底。WGS84 结果转换为 GCJ-02 后更新标记、地图中心与围栏；显示定位精度，点击“确认位置”才写入活动表单，保存活动后才持久化。
- 定位拒绝、超时、不支持、坐标无效或不安全上下文均明确提示；不以默认城市或 IP 定位代替成功。定位中禁止确认；失败后保留已有选点，新活动没有选点时禁止确认默认城市。
- 搜索、手动选点、切换到坐标备用方式、关闭或重新打开弹窗均使旧定位回调失效，防止晚到结果覆盖用户选择。只接受从地图容器内部开始的选点手势，忽略打开弹窗时遗留的 SDK 点击事件。
- 功能只用于后台活动中心选点，参与端签到仍使用既有定位与后端围栏规则，没有增加参与者手选位置通过签到的路径。

## 自动验收

本机真实 MySQL 测试库 `herenow_test`、独立临时管理员和临时活动；Chromium 加载实际构建产物。用户已配置本地高德 JS API Key 和配套后端安全密钥，验收过程中未输出密钥值。

- 52 项测试通过；类型检查、ESLint、前后端构建、参与端拆包检查、改动代码格式检查与 `git diff --check` 通过。参与端入口及静态依赖约 109.6 KB gzip，地图依赖仍局限于后台。
- 真实高德 SDK：底图和标记／围栏显示，POI 搜索“宁波诺丁汉大学”并选择候选，主动重新定位、确认中心、保存草稿、刷新回显，以及已有中心再次打开后不自动定位。代理初始化与搜索请求正常，无失败请求或页面运行时错误。
- 浏览器模拟 WGS84 点 `121.5649, 29.8006`、精度 8 米；实际显示／保存 GCJ-02 点约 `121.569020, 29.797985`。与锁定版本 gcoord 的结果核对，验证没有把浏览器坐标直接当作高德坐标。
- 真实 SDK 使用 1,440 px 和 390 px 截图复核，地图定位与操作控件可用。
- 独立浏览器场景注入模拟 SDK／定位返回，17 项断言通过：拒绝、授权后重试、请求选项、超时、不支持、无效坐标、定位中禁止确认、手选后忽略旧结果、关闭重开忽略旧回调、新请求有效、搜索后忽略旧结果、搜索选点可确认，以及 SDK 遗留点击不能取消／覆盖自动定位。无运行时异常。
- 真实 SDK 联调补齐固定的 `/v3/log/init` 初始化路径和 SDK 必需的参数白名单，保持重复参数顺序；代理仍限制目标、参数、后台鉴权、响应大小与超时，不开放任意 URL 转发。

本地脚本、检查结果与截图保存在忽略目录 `output/playwright/`。临时账号与活动在验收结束后清理，不修改用户实际活动。

## 限制

真实高德服务已联调；定位返回使用浏览器模拟坐标，并非电脑／手机的真实 GPS 结果。尚未验证 iOS Safari、微信、安卓真机权限、现场精度、软键盘、实际安全区或生产域名与配额，不视为 Spec 第 15 节全部验收通过。
