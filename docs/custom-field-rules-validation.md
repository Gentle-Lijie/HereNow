# 自定义字段重复规则验收

日期：2026-10-14。依据 Spec v1.4 第 5、6、9、11、15 节。按用户最新指令取消固定身份类型与系统身份输入，多个字段分别校验重复。

## 行为与兼容

- 新活动不需要身份字段，也不自动生成报名编号。自定义字段新增 `allow_duplicates` 开关，默认允许重复；关闭后该字段的非空值在活动内独立唯一。多个字段不是组合唯一，任意一个冲突即拒绝。必填与重复规则独立，可选空值不参与判重；文本回答保留原样，比较时做明确的规范化。
- 全部允许重复时，同内容可以通过不同签到会话多次提交；同会话原幂等键／原请求体仍恢复同一个结果。错误提示明确指出冲突字段，不回显他人的值或回执。
- 名单导入／准入通过一个普通字段的 `roster_match` 配置匹配启用名单。该字段在名单内唯一，但它的重复开关独立控制是否允许同一名单记录多次签到。导入预览和最终事务检查匹配字段以及不允许重复的其他字段，跨批次竞争不能产生半批生效。
- 尚无名单或签到数据时，包括已发布活动，管理员可修改或移除字段；有数据后已有结构锁定，名称、重复／大小写规则仍可调整，并可添加非必填字段。收紧规则先在活动排他锁内重建索引，有已有冲突就回滚。结构或重复规则改变使未完成会话失效；活动结束后不可编辑。
- 签到页、人工补签、记录列表、导出和导入模板统一使用配置字段。记录使用独立签到编号区分；没有隐藏的系统身份提交参数。旧请求的身份参数仅保留用于取回迁移前已成功的原幂等结果，不能新建签到。

## 数据迁移

`002_field_uniqueness.sql` 创建 InnoDB 唯一值表，约束为 `UNIQUE(event_id, field_key, value_digest)`。值摘要使用服务端 HMAC；签到、所有唯一值声明、证据和会话消费在同一事务提交。在线、人工、审核／撤销／恢复遵守同一规则，撤销不会释放唯一值声明。

`003_custom_fields.ts` 将旧固定身份输入转换为可见的普通字段，保留名称、类型、必填、大小写和防重复行为，补齐历史回答、名单与唯一声明；每个活动原子迁移且可重试，不覆盖已有新字段回答。旧活动没有数据时可删除这个转入的字段。保留旧记录与成功幂等回执，失效旧未完成会话及导入预览；服务启动检查迁移版本，旧备份恢复后须先迁移再开放。

本机业务库迁移前已备份到 `output/backups/herenow-2026-10-14T07-20-27.585Z.sql`。实际迁移 2 个活动，原有签到／名单记录数均为 0；指纹核对无数据丢失或回答改写。另在真实 MySQL 测试库构造非空历史签到与旧幂等结果，验证补齐字段、去重回填、过期会话恢复原成功结果以及重复执行不重复迁移。
