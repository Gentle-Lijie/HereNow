# HereNow 开发规范

版本：v1.0 · 2026-10-13。依据：`spec.md` v1.4。前端 Vue 是用户已确认约束；具体 UI 库、后端组合及参数沿用 Spec 建议作为开发起点，部署策略仍需按实际环境确定。2026-10-14 已建立应用脚手架并实现核心开发版本；实际功能与验证范围以 `docs/implementation-status.md` 为准。

## 1. 范围与实施顺序

围绕活动、名单、动态活动码、签到、人工核验和导出构建单空间工具，通常每场不超过 1,000 人。参与者使用 H5，无注册、无短信；后台账号由部署方创建。P0 全部完成并验证才具备首期上线条件，P1／P2 不自行扩大范围。

每阶段交付可演示的纵向闭环：

1. 核心：账号与活动授权、活动配置、字段、名单、动态码、签到事务与记录查询。
2. 现场：短时会话、原生定位／来源适配、地图选点、坐标标准化、围栏、可信 IP、限速与人工处理。
3. 完整性：响应式、导入预览、导出、审计、隐私说明、清理与备份恢复。
4. 上线验证：真机扫码与定位、现场测点、并发与幂等压测、暂停演练。

权限、去重和安全凭证随相关功能一起实现，不等到最后补做。演示数据不能进入真实名单，模拟定位只能出现在明确的开发／测试环境。

## 2. 技术栈与目录

| 范围      | 开发基线                                                      |
| --------- | ------------------------------------------------------------- |
| 前端      | Vue 3、TypeScript、Vite、Vue Router                           |
| 后台 UI   | Ant Design Vue 4 的兼容维护版本                               |
| 参与端 UI | Vant 4 的兼容维护版本                                         |
| 前端状态  | 优先 composable／组件局部状态，跨路由确有需要时采用 Pinia     |
| 后端      | Node.js 在支持期内的 LTS、TypeScript、Fastify                 |
| 校验      | 共享业务 schema 与运行时校验；初始化时选择一种成熟方案        |
| 数据库    | MySQL 8.4 LTS、InnoDB、utf8mb4                                |
| 地图      | 中国大陆为当前选型假设，高德 JS API 2.0；转换模块与服务商解耦 |
| 部署      | 单应用进程 + 本机 MySQL，页面与 API 同源                      |

建议采用单仓库 workspace，初始化时确认 npm 或 pnpm 并只提交对应的一份锁文件。依赖锁定具体版本，不用浮动 `latest` 作为可复现构建依据。数据库访问库、CSV／XLSX 库、签名库在初始化阶段按维护性、许可和实际功能选择；不提前强制某个 ORM。不默认引入 Redis、消息队列、微服务、图表库或完整管理框架。

目录职责约定（实际文件以仓库为准）：

```text
apps/
  web/src/
    app/                    # 路由、入口、运行时配置
    admin/                  # 后台页面与字段渲染器
    checkin/                # 手机表单、定位状态与结果
    display/                # 独立二维码展示
    components/             # 真正共用的基础组件
    composables/            # 通用 Vue 逻辑
    services/               # API 客户端、LocationAdapter、地图加载
    styles/                 # 公共基础样式及各使用面的主题
  api/src/
    modules/                # auth、events、participants、checkins 等
    plugins/                # 数据库、会话、鉴权、可信代理
    services/               # 凭证、CoordinateService、保留期等
    jobs/                   # 证据与临时文件清理
    config/                 # 环境配置校验
packages/
  contracts/src/            # 无前后端框架依赖的 DTO、schema、错误码
database/migrations/        # 版本化 DDL
tests/                      # 跨模块集成、E2E 与压测
docs/                       # 规范、运行说明与验收证据
```

导入方向：web／api 可引用 contracts；contracts 不引用 Vue、Fastify、数据库或服务器密钥。路由处理请求与响应，service 执行业务，repository 执行 SQL；UI 不直连数据库。

## 3. Vue 与界面规范

页面背景统一纯白；后台与参与端使用紧凑间距，按钮中的 SVG、加载图标与文字垂直居中。页面标题直接说明功能，移除宣传标语、装饰封面与无实际操作价值的场景描述。参与端保留活动信息、字段、定位、隐私同意、会话时效和结果／错误反馈；不得以精简元素为由删除必要的规则或隐私说明，也不得缩小移动端点击目标或输入字号。

- SFC 使用 Composition API、`<script setup lang="ts">`；组件 PascalCase，composable 命名 `useXxx`，业务变量 camelCase，API 与数据库字段沿用 Spec 的 snake_case。
- Props／Emits 显式类型化，props 不直接修改；使用稳定业务键作为 `v-for` key。表单草稿、请求状态与服务器结果分离。
- 定时器、监听器、地图实例、定位回调与未完成请求在路由切换／卸载时清理；过期异步回调不能覆盖新状态。搜索防抖并取消或忽略旧响应。
- API 调用集中到 services，组件不得散落拼接 URL、凭证和错误码。无需全局共享的数据不放入 Pinia；敏感会话由 HttpOnly Cookie 持有。
- 共享字段定义、校验和类型；后台用 Ant Design Vue 渲染，参与端用 Vant 渲染。名单权威值由后端决定，不能仅用 readonly 保证。
- 全局样式控制范围，避免后台与手机主题相互覆盖；页面样式优先 scoped，确需深层样式时核对对应 Vue 库的公开扩展接口。
- 不使用任意 `v-html` 展示管理员配置、名单或用户输入，不从字符串执行脚本。

后台、签到和展示页路由动态导入；共享入口不静态导入后台组件库。手机签到首次加载不含后台表格、名单解析或地图 SDK。地图只在选点、只读查看或经过验证的定位回退时加载。发布时用构建产物检查实际拆包和压缩传输体积。

手机签到单列、建议最大宽度 560 px；点击目标至少 44×44 CSS px，输入字体至少 16 px，允许缩放、长中文换行与 200% 缩放。字段错误就近展示并定位到首个错误；底部按钮兼顾软键盘与安全区。后台手机记录使用卡片，筛选用抽屉，选点用全屏或足够大的抽屉；字段排序除拖动外提供上下移动按钮。

| 宽度（CSS px） | 项目布局                         |
| -------------- | -------------------------------- |
| 320–767        | 手机单列、卡片记录、全屏选点     |
| 768–1,023      | 平板折叠导航、简化表格           |
| ≥1,024         | 桌面完整导航、表格与并排地图设置 |

展示页独立布局、本地生成二维码，保留静区和对比度；过期码立即隐藏，断网展示异常，恢复后换新码。倒计时依据服务端到期时间，不能当作服务端验签依据。空、加载、失败、重试、已结束和待核验均有明确文案，不只用颜色表示状态。网络超时不能显示成功，`PENDING_REVIEW` 不计成功。

## 4. API、校验与身份

- API 路径、响应码和业务含义遵循 Spec 第 12 节；统一包含 `code`、`message`、`request_id`，响应成功状态与 HTTP 状态保持一致，列表限制分页与排序参数。
- 所有边界输入运行时校验。字段必填、类型、选项、长度及未知字段在后端验证；客户端错误用于改善体验。
- 不设置固定身份类型或必需的系统身份字段。普通字段的 `allow_duplicates` 默认 true，false 时各字段独立校验非空值；全部允许重复时仍保持会话幂等。字符串字段保留前导零，不把编号改成数值。
- 字段值摘要使用带密钥 HMAC，绑定活动、字段键、类型及规范化值；原始文本回答保留，大小写折叠仅用于比较，手机号按字段类型规范化。
- 没有名单或签到数据前可修改或移除字段；有数据后冻结已有字段结构，允许增加非必填字段及改名称／重复规则。重复规则变更须在活动排他锁事务内重建索引，有冲突回滚；结构及重复规则变更更新 `policy_epoch`，文案变更仅更新表单版本。
- 内部 BIGINT 在驱动中保持无损，在 JSON 中序列化为字符串。日期时间 API 使用明确时区的 ISO 8601，存储 UTC，展示使用活动时区。
- 活动由已验证会话确定，不允许提交体切换活动。公开端不提供名单枚举接口；重复身份统一提示现场核验，查看详情需要原会话或回执凭证。

建议默认参数集中配置并做范围校验：二维码 30 秒刷新／45 秒有效，会话 120 秒且不滑动续期，定位首轮 10 秒／总体最多 20 秒，字段最多 30 个、文本 2,000 字符、请求体 64 KB，导入 5 MB／10,000 行。围栏建议 R=200 m、A=100 m；这些均是开发起点，不能当作已现场验证值。最终保留期、地域、地图授权、字段模板和部署设置登记在配置文档中。

## 5. 数据库、事务与幂等

必须提供可审阅的版本化迁移，实际表与 Spec 第 11 节对齐。字段摘要使用 `BINARY(32) NOT NULL`，字段键与活动外键非空；签到防重复以 `checkin_field_values` 的 `UNIQUE(event_id, field_key, value_digest)` 兜底。名单匹配字段摘要保留 `(event_id, identity_digest)` 唯一约束；签到旧摘要列只用于兼容和随机记录标识。时间为 UTC `DATETIME(3)`，连接设置 UTC；JSON 存可变字段，常用筛选维度使用普通列与明确索引。核心凭证摘要唯一，幂等键在会话作用域唯一。

所有在线／人工路径遵守统一锁顺序：活动 → 会话 → 名单 → 签到 → 字段唯一值声明／幂等。活动检查采用共享锁，暂停／规则更新采用排他锁；会话和资格锁定后再确认。文件解析、网络请求和坐标转换在锁外完成，事务内重新验证规则与资格，不持锁等待定位或外部服务。

提交在同一事务内写签到、证据与必要结果引用、消费会话并写幂等记录。先验证浏览器绑定、CSRF／Origin，再查询已有幂等结果；同键同内容取原结果，同键异内容冲突。已成功请求在保留期内可读，即使活动关闭或会话过期；读取当前审核状态，不重新签到。失败事务不得消费唯一会话或留下半笔成功。

字段唯一冲突回滚后返回统一提示，不读取或回显其他签到的资料；原成功幂等请求仍优先恢复自己的结果。死锁／锁超时有界退避，建议最多 3 次，保持原幂等键和内容。不得用 `INSERT IGNORE`、`REPLACE INTO` 或无约束的先查后写规避错误。撤销／恢复修改同一签到行并审计，不能新增记录绕过唯一性。

## 6. 动态码、定位与地图

二维码载荷含活动、用途、签发／到期时间、规则版本和密钥版本，固定签名算法、限制长度，不含个人信息。token 放 URL fragment，由 HTTPS POST 换会话后清理；第三方 SDK 加载前清除 fragment。码可多人使用，会话只绑定一个浏览器、活动及表单／规则版本。展示接口只供后台账号或只读展示会话访问。

定位默认优先标准 Geolocation，来源与坐标系由适配器明确给出；iPhone 和安卓不能采用不同的猜测规则。后端来源白名单、有限数值、经纬范围、正精度校验，并使用 CoordinateService 统一 WGS84。保存原点、坐标系、转换版本、验证地域和转换误差预算；地图保存原 GCJ-02 点，避免重复转换漂移。

后端计算 Haversine 距离 d，按 Spec 使用 `a = accuracy + conversion_error_budget_m`：精度超过 A 则不足；`d + a <= R` 才自动通过；`d - a > R` 为范围外；其余为边界不确定。未知坐标、IP 定位、转换失败或未验证地域不能通过强制围栏。关闭定位不请求权限／存坐标；记录模式允许失败但记录原因；强制模式失败需重试或有权限的人工处理。

高德安全配置在 SDK 脚本加载前设置同源 `serviceHost`，`AMAP_SECURITY_JS_CODE` 仅在服务端代理中注入。代理验证后台管理员身份，限制上游路径／参数、请求频率、超时与响应体大小，不转发浏览器 Cookie／认证头或跟随重定向。

管理员未设置中心时打开选点弹窗自动尝试浏览器定位；已有中心保持原位，并提供主动定位／重试按钮。标准 Geolocation 结果按 WGS84 转为 GCJ-02 显示。拒绝、超时与不支持明确反馈；取消、关闭、手动选点或搜索后忽略过期定位回调，不让晚到的定位覆盖用户选择。

地图交互覆盖搜索候选、点选／拖动、半径预览、确认、取消和准确回显；修改围栏更新 `policy_epoch`。 地图配置缺失需明确提示，SDK 加载失败应清理失效脚本并支持重新加载；组件关闭后忽略过期回调。未保存中心且进入坐标备用路径时，不得自动填入演示坐标供直接确认。参与端只能展示采样位置，不允许手选坐标签到。地图故障不阻塞无需地图的既有签到；强制活动无可靠中心不能发布。

## 7. 导入、安全与保留

CSV／XLSX 先限文件大小、解压体积、单元格与行数，再选择工作表、映射、预览并确认。拒绝宏、公式单元格、外部链接和未知字段；按名单匹配字段及不允许重复字段查文件内／库内重复，输出行号原因。支持仅新增和按名单匹配字段更新，错误整批拒绝，最终单事务生效；不执行 DDL、不静默跳过、不覆盖历史签到快照。

XLSX 导出用户文本为显式字符串，CSV 对公式起始字符做安全处理；引号包裹不能替代公式注入防护。导出字段明确选择，默认不含原始 IP／精确位置，操作员默认无导出权限。

全站 HTTPS；Cookie 使用 Secure、HttpOnly 和适合入口的 SameSite 设置，写 API 校验 CSRF／Origin。管理会话与展示会话权限分离，后端逐次校验空间、活动、角色。使用成熟密码摘要、参数化 SQL 和登录限速；可信代理列表明确，不能信任任意转发头。限速容纳同一现场 Wi-Fi 的多名用户，不用“一 IP 一人”。

签名、身份摘要、数据加密使用分离密钥；配置通过环境或部署密钥管理注入，仅提交不含秘密的示例。日志不包含二维码 token、Cookie、原始表单、完整主键、个人口令或精确位置。证据加密、单独保留，查看原始证据需额外权限与审计。

建议起点：结果／名单 90 天、风险证据和失败尝试 7 天、审计 180 天、临时导入与过期会话／幂等信息 24 小时，具体起算点按 Spec 第 13 节。定期清理业务表、关联日志和暂存文件，备份按轮转期保留；恢复后重放删除记录。上线前实测恢复和清理，不能把建议期限当成通用合规结论。

## 8. 验证与交付

脚手架建立后统一提供 `dev`、`typecheck`、`lint`、`test`、`build` 脚本，并写明运行方式。类型检查覆盖 `vue-tsc`、后端与共享包，lint 覆盖 TypeScript／Vue。测试建议 Vitest、Vue Test Utils 和浏览器 E2E 工具；数据库集成必须在真实 MySQL 8.4 上运行。这些脚本现已提供；实际检查结果登记在实施与验收记录中。

| 改动范围         | 必要验证                                                                               |
| ---------------- | -------------------------------------------------------------------------------------- |
| 身份／字段／坐标 | 规范化、前导零、未知字段、已知坐标、重复转换、边界与精度失败                           |
| 签到事务         | 同不允许重复字段值 20 个并发请求唯一，允许重复时独立落库；失败回滚不消费会话；同键异内容；已结束／过期后的原结果读取   |
| 活动／名单／审核 | 暂停与提交、停用与提交的竞争顺序，人工补签去重，撤销恢复不新增，权限与审计             |
| 二维码／回执     | 篡改、过期、错误用途／活动／版本、多用户共用码、公众无签发权限、他人详情不可读         |
| 导入导出／隐私   | 超限与异常 XLSX、公式拒绝、整批回滚、字符串导出、日志脱敏、保留期清理及恢复后删除      |
| Vue UI           | 表单提交状态、错误定位、懒加载、地图确认取消、异步竞争、弹层／监听器清理及各使用面交互 |

响应式至少检查 320、375、390、430、768、1,024、1,440 px、横竖屏、安全区、软键盘和 200% 缩放。手机实测覆盖 iOS Safari、微信内置浏览器、安卓常用浏览器的扫码、Cookie、定位与提交；桌面模拟不替代真机结论。

约定环境压测 100 次提交／秒加混合流量，目标 P95 ≤500 ms、非预期 5xx <0.1%、无重复落库和丢失成功回执。参与端首次自有 JS 压缩传输预算 ≤250 KB，地图按需部分另计。记录资源、版本、数据集、方法与结果，达标前写“待验证”。

每次功能交付列出对应 Spec 章节／验收场景、实际通过的检查、未测项与必要配置；遵循 Spec 第 15 节完整验收矩阵。分支默认 `codex/主题`，保持变更聚焦，提交描述说明实际行为。需求或参数改变同步 Spec；可选依赖与架构改变记录理由及影响。
