# 身份字段与地图接入修复验收

日期：2026-10-14。对应 Spec 第 5.2、5.3、8.5、8.6、15 节。

## 原因与修复

身份字段名称被前后端与身份类型、大小写规则一起冻结。现保留已发布活动的身份类型和规范化规则锁定，允许活动结束前修改显示名称。只改名称不更新规则／表单版本，不影响既有会话、身份去重或记录。界面明确解释锁定范围；已结束活动仍禁止编辑。

地图报错直接原因是本地 `VITE_AMAP_KEY` 为空，原提示错误地表达为临时服务故障；此前也未接入高德配套安全代理。现按[高德官方安全配置说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)完成以下处理：

- SDK 加载前设置 `_AMapSecurityConfig.serviceHost` 为同源 `/api/_AMapService`；安全密钥 `AMAP_SECURITY_JS_CODE` 仅由后端注入上游请求，不进入前端代码或浏览器安全配置。
- 后台管理员鉴权后才可查询配置就绪状态或访问代理。代理仅允许固定的SDK 初始化／地点搜索／地图样式路径与参数，覆盖客户端传入的 Key／jscode；不转发 Cookie、认证头或任意目标 URL，不跟随重定向。请求限速、8 秒超时、响应最大 2 MB；错误只返回固定提示，避免泄漏上游 URL 中的密钥。
- 区分未配置、网络失败、超时与初始化失败，增加真正的重新加载操作。并行 SDK 加载复用同一请求，失败清理脚本／定时器后可重试。
- 确保弹窗容器已挂载，关闭／重新打开时忽略过期初始化与搜索回调，清理地图和搜索计时器。搜索失败与无结果分别提示。
- 未保存中心时，手工备用经纬度为空；坐标或半径不合法、加载中或没有可用地图时不能直接确认。保留原坐标系、确认生效与取消不生效的语义。

## 尚需配置与限制

初次验收时未提供有效 Key 与配套安全密钥，随后用户已完成本地配置。后续真实 SDK 与当前位置功能联调结果见 [管理员当前位置定位验收](admin-location-validation.md)。真实手机现场定位精度、合法域名的生产部署与服务配额仍需对应环境验证，不能将浏览器模拟坐标视为真机 GPS 验收。
